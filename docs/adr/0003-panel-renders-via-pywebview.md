# Панель рендерится через pywebview, окно настроек — через customtkinter

Первая реализация панели (`winhotkeys/panel.py`) использовала
customtkinter/Tk, как и остальной GUI проекта. Утверждённый макет
(`docs/tasks/sidebar-panel-ui-mockup/`) требует, чтобы свёрнутая капсула
раскрывала имя+хоткей строки по наведению — анимация роста ширины строки,
выраженная в макете как пара CSS-переходов (`max-width`/`opacity`). В
Tkinter это потребовало бы ручной покадровой анимации геометрии через
`place()` вместо `pack()`/`grid()` — хрупко и не даёт того же блюра
(`backdrop-filter`), что в макете.

Решение: панель рендерится через `pywebview` (реальный HTML/CSS в
WebView2) — CSS почти дословно взят из макета, hover-анимация и блюр
работают из коробки. Проверено на месте: методы окна pywebview
потокобезопасны (можно звать `show()`/`hide()` из фонового потока без
дополнительной синхронизации), в отличие от Tk, что здесь же упростило
код триггера "hotkey" (без него понадобилась бы `queue.Queue` — ранний
вариант с ней остался только в истории git).

Окно настроек (`settings_window.py`) осталось на customtkinter — оно не
требует CSS-анимаций, было явно вне объёма визуальной точности макета
(два раздела навигации — заглушки), и полная миграция обеих поверхностей
разом не была нужна для решаемой проблемы. Два разных GUI-стека в одном
небольшом проекте — осознанный компромисс, а не забытая недоделка.
